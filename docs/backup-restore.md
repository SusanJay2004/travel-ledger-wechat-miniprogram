# 备份、恢复与回滚

`cloudfunctions/backup` 每天导出权威集合为 gzip 压缩 JSON，并保存到客户端不可读的 `private-backups/` 云存储路径。每天按北京时间自然日使用唯一 ID `bak_YYYYMMDD`，每次实际尝试写入独立的 `attempt_<随机令牌>/` 前缀；`backup_manifests` 留下状态、尝试次数、租约、集合页数、文档数和 30 天到期时间。

微信定时触发器可能重复投递。首个调用在数据库事务中取得 20 分钟租约；同日完成态直接复用，租约内运行态不重复导出，失败态或过期租约才允许下一次尝试接管。部署模板把事件函数最大执行时间固定为 900 秒，租约严格更长，旧实例不能在新实例接管后继续运行。

每页上传前先把确定性云路径写入运行中的 manifest，上传后再用文件 ID替换待上传路径；即使进程在上传成功和 ID 持久化之间被强制终止，接管者也能利用官方“同路径上传会覆盖”的语义写入无敏感占位文件、取得 fileID 并删除。已登记的旧文件和待恢复路径必须全部清理成功，才允许新尝试导出；清理失败保持失败态供当天再次安全重试。最终 manifest 上传也采用相同登记规则；最终数据库提交响应丢失时重新读取权威完成态，不把已成功备份误标失败或删除。

过期清理每次按 20 条循环，删除 manifest 登记的文件 ID，并恢复删除仍停在待上传路径的文件，直到所有到期备份清理完成。

集合导出按 `_id` 升序游标分页，不使用 `skip`，因此导出期间删除前页文档不会导致后页记录被跳过。它仍然是在线逐集合导出，不是跨集合原子快照：运行期间发生的写入可能形成前后时点混合。恢复时必须执行下述关系与金额校验；规模增长或平台开放原生时间点备份后，应升级为原生快照，并继续保留本导出作为可读的灾备副本。

不备份可重建或短期数据：`sync_events`、`idempotency_records`、`rate_limit_records`。头像与个人二维码属于云存储文件，生产环境还需启用云开发存储版本/回收策略或平台快照；数据库导出不等于文件备份。

## 安全要求

- `backup` 明确只接受 `getWXContext().SOURCE === 'wx_trigger'` 的官方定时触发器；仅仅缺少小程序用户 `OPENID` 不足以通过鉴权。
- `backup_manifests` 禁止客户端读写；`private-backups/` 禁止客户端读取、列举、覆盖和删除。
- 备份日志只输出集合数、文档数和受限错误码，不输出备份/尝试 ID、云路径、用户资料、`OpenID` 或账单内容。
- 生产恢复必须先恢复到隔离环境，不得直接覆盖在线集合。

## 季度恢复演练

1. 选取一个已完成且校验成功的备份 manifest，核对全部页文件存在。
2. 在隔离云环境按 manifest 顺序解压并导入集合；保留 `_id`，禁用任何面向真实用户的触发器与订阅通知。
3. 校验用户数、行程数、每行程 `totalCents`、有效账单数、成员关系和公开 ID 唯一性。
4. 随机选择至少 20 段行程重新计算摘要和分账，和备份前记录对比。
5. 记录恢复耗时、缺失/不一致、操作者和结论；演练数据随后按流程销毁。

## 生产回滚

- 应用代码：保留上一稳定上传版本；发现回归先关闭新功能开关，再由微信后台回退。
- 数据库：普通应用发布不做破坏性迁移。若未来拆分账单集合，必须先双写/双读校验、完整备份并提供反向脚本。
- 故障期间：将小程序切换为只读维护提示，禁止在不确定状态下重复写入或直接导入备份覆盖新数据。

备份和恢复只有在真实云环境成功演练并留存记录后，才能视为发布门禁通过。

平台语义依据：微信开放文档明确说明 [`Cloud.uploadFile()`](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloud/reference-sdk-api/storage/Cloud.uploadFile.html) 上传同一路径会覆盖；CloudBase 事件函数最大超时配置为 900 秒。真实环境烟测仍是发布门禁，文档说明不能代替实际验证。
