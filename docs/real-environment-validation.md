# 真实云环境与真机验收手册

本手册用于完成发布检查表中的真实 AppID、云环境、真机、多人、弱网、运维和公开搜索门禁。它不替代微信后台审核，也不能用开发者工具模拟器结果代替真机证据。

## 证据与隐私

- 每次测试记录日期、环境、`solo|collaboration` 模式、Git commit、体验版版本、测试者代号、设备型号、系统版本、微信版本、开始/结束时间和结论。
- 原始截图、录屏、云日志和导出文件只放在本机 `test-evidence-private/`；该目录已被 Git 忽略。公开仓库只记录脱敏摘要，不保存头像、用户名、`OpenID`、真实账单、环境 ID、AppID 或联系方式。
- 所有测试账号使用虚构用户名与账单；多人测试者须知情同意。失败证据要记录复现步骤、预期、实际结果和关联 issue，不能只写“未通过”。
- 每个门禁必须有可核对的截图或日志；勾选清单本身不算证据。

## 1. 云环境部署验收

1. 核对开发与生产是两个独立环境；截图只保留环境别名，公开摘要不得写环境 ID。
2. 按 `cloud-deployment-manifest.md` 创建全部集合、唯一/组合索引、数据库规则和云存储规则。
3. 部署 `api`、`avatar-review`、`maintenance`、`backup`，确认云端安装依赖成功；记录每个函数的部署时间和版本。
4. 配置 `PRODUCT_MODE`、`MINIPROGRAM_ENV_VERSION`；体验/生产不得存在 `CONTENT_SECURITY_MODE=disabled`。
5. 把 `wxa_media_check` 消息推送指向 `avatar-review`。上传正常 JPG/PNG，确认旧头像在审核中继续展示，回调通过后才切换；记录真实回调 `SOURCE` 是否被当前鉴权接受。
6. 验证非 JPG/PNG、超过 1 MB、其他用户目录文件和客户端越权写权威集合均被拒绝；客户端不能写 `profile-codes/`、不能读写 `private-backups/`，只能删除自己创建的 `avatars/` 文件。
7. 手动触发定时函数的官方测试方式，确认 `maintenance` 与 `backup` 只接受 `wx_trigger`；客户端、开发者工具、HTTP 和其他云函数主动调用均被拒绝。

## 2. 单人主流程（iOS 与 Android 各执行一次）

1. 首次进入并确认隐私提示；退出后重新进入仍回到同一账号，公开 ID 保持不变。
2. 修改用户名、签名和头像；覆盖默认值、非法字符、超长文本、审核中提示和审核失败关闭。
3. 创建无日期行程，再依次插入较晚和较早日期，确认首页、年份分组和详情时间线升序。
4. 创建有效账单、零份额账单、付款人不在参与人、多付款人，以及份额/实付不守恒的无效账单。
5. 验证总支出包含无效账单，但结算排除无效账单；分别执行“修改”和“忽略”，前者定位第一条无效账单，后者显示忽略数量与金额。
6. 验证账单跨日期移动、软删除、活动记录恢复、完结冻结、重新开启、个人归档、恢复和清空。
7. 退出登录后验证本机状态被清理；重新进入后权威数据仍在。最后用专用测试账号演练注销、文件清理和以同一微信身份建立新账号。

## 3. 三账号协作流程

仅在平台门禁允许且开发环境设置为 `collaboration` 时执行。

1. A 用公开 ID 搜索 B、用小程序码搜索 C；验证申请、同意、拒绝、删除、拉黑和解除后的权限。
2. A 在好友列表一次勾选 B、C 发出行程邀请；验证 7 天有效期、重复邀请幂等和被邀请人首页满 100 条时拒绝加入。
3. A、B、C 同时打开同一行程；一人改名、一人加日期、一人加账单，确认在线成员 3 秒内收到同步并重新拉取权威版本。
4. 两台设备基于同一旧版本同时修改同一账单，确认一方得到明确冲突提示且不会静默覆盖；刷新后重新应用修改。
5. 覆盖付款人不在参与人、A 为 B/C 承担份额、多人付款和无效账单忽略，三台设备看到相同结算版本与逐分一致结果。
6. 验证成员被账单引用后不能中途退出；完结后各自归档互不影响，重开时首页容量检查生效，永久脱离者不能重新读取或写入。

## 4. 容量、性能与弱网

- 在开发云环境写入 20 人、100 条有效账单和 400 条恢复期内软删除账单的最大字段样例，确认文档可写、可读、可更新，结算在目标设备 2 秒内完成。
- 在 99 条首页行程时由两台设备并发创建，确认严格只有一条成功且计数为 100；对邀请加入、归档、恢复、重开和退出重复容量守恒测试。
- 首页、消息和活动记录分别写入超过 100 条数据，验证游标分页无重复、无遗漏，常用列表在正常网络下 2 秒内可交互。
- 用开发者工具弱网面板辅助复现，再在 iOS/Android 真机执行断网、超时和恢复联网：缓存只读可见，共享写入不在后台排队；传输结果不确定时保持内容不变再次点击，确认客户端复用原 `requestId`，或重新拉取权威数据，且不产生重复行程、账单、申请或邀请。
- 将系统字体调大并覆盖小屏/刘海屏，确认核心文字不截断、固定按钮不遮挡内容、触控区域不小于 88rpx。

## 5. 故障、备份与恢复演练

1. 在开发环境临时阻断一次审计或同步投影，确认账本写入成功且 outbox 保留；恢复后运行维护，确认投影补齐、outbox 清空且确定性 ID 无重复。
2. 让一次头像或二维码文件删除失败，确认用户文档保留待删清单；恢复后运行维护，确认文件和标记最终清理。
3. 运行备份并核对 manifest、全部分页文件、文档数和到期时间；验证客户端无法读取 `private-backups/`。
4. 按 `backup-restore.md` 恢复到隔离环境，核对用户/行程数量、金额、成员关系与公开 ID 唯一性，并重算至少 20 段行程。
5. 演练关闭协作开关、回退上一稳定小程序版本和只读维护提示；记录恢复时间与数据一致性结论。
6. 配置 `operations.md` 中的错误率、投影、头像回调、维护、备份、资源和预算告警，并主动触发一次测试告警证明通知链路有效。

## 6. 灰度、审核与公开搜索

1. 用 5–10 个知情同意的小团队进行灰度，记录团队规模、设备覆盖、完成流程、问题级别和修复版本，不记录真实账单。
2. 所有阻断问题关闭后，在 iOS/Android 上重跑单人主流程；若提交协作版，再重跑三账号流程。
3. 按 `store-listing.md` 上传与实际模式一致的名称、图标、简介、关键词、隐私文本、演示路径和体验版截图。
4. 微信审核通过后由管理员发布，等待搜索索引生效。
5. 使用一个非开发者、非体验成员微信账号，从微信搜索进入，完成首次打开、创建行程、记一笔和计算分账；保存脱敏录屏与正式版版本号。
6. 核对监控、预算告警和上一稳定版本回退入口仍可用，最后更新 `release-checklist.md` 的证据引用。
